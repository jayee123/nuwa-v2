### 額度顯示改讀新表（連帶）

`users.dialog_limit` 失去唯一的消耗端（只有公版 AI 在扣），數字已無意義。三個地方改成讀跨 App 新表 `ai_dialog_usage`：

| 位置 | 之前 | 現在 |
|---|---|---|

## 二、金流：回呼驗簽補洞（09-26，已上線）

**`/api/payment/callback` 的 ChkValue 以前是「有帶才驗」。** 使用者自己 initiate 拿到 Td（表單參數裡就有），再 POST 一個不帶 ChkValue 的回呼，就能把自己的 pending 標成 paid、白拿一個月訂閱。

現在 Td、MN、ChkValue 缺任一個直接 400，驗簽在查訂單之前。e2e 補了「不帶 ChkValue 回 400」、「缺 Td／MN 回 400」兩條，正式站實測通過。

### 金流現況（09-26 查證）

| | |
|---|---|
| 紅陽三支 URL（DB `secret_params`） | 全指 **test.esafe.com.tw 測試環境** → 正式站現在可以刷假錢測 |
| `gateway_transactions`（027 帳務表） | 0 筆，建好後從沒真正跑過一次金流 |
| `payments` | 45 筆，全是 4/30 的舊測試；9/10 有一筆 NT$5 pending 沒走完 |

### 金流上架前必修（你的金流規格書可以收進去）

1. ✅ 回呼驗簽必填（本次已修）
2. **`DEVLOG.md`（nuwa 根目錄，V1 時代）有紅陽測試環境整組憑證，和正式環境的 AES key／IV、正式商店代號，明碼在 git 裡。** repo 是 private，但那組正式 key 應視為已外洩：上正式前請紅陽重發，並把那段移除。
3. `NEXT_PUBLIC_SITE_URL` 要確認是 `https://next.nuwa.chg2asc.com`（Jeff 在 Vercel 後台看）。舊網域對 POST 回 308，紅陽伺服器回呼不一定跟著轉。
4. 切正式：三支 URL 換 `www.esafe.com.tw`、正式商店代號、正式密碼，全在 `secret_params` 改，不用重部署。
5. `auto-charge` 不看紅陽 errcode（已知，等規格書）。
6. 月扣 cron 是「掃所有今天到期的 active 訂閱全部扣」，不能指定一個人；現在 17 個 active Premium 都會被掃到。實測前先確認那 17 個都是團隊帳號。
